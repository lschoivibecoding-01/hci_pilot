# 방 사진 검색 실험 도구 · 진행 매뉴얼

참여자가 방 사진을 검색하고, 마음에 드는 사진을 모아, 최종 1장을 고르는 실험 도구입니다.
설치할 것은 없고, 아래 주소를 브라우저로 열어 쓰면 됩니다.

| 화면 | 주소 | 누가 |
| --- | --- | --- |
| 첫 페이지 | https://projectmuyu.github.io/hci_pilot/ | 두 화면으로 가는 링크 |
| **검색 화면** | https://projectmuyu.github.io/hci_pilot/search_system.html?view=search | 참여자 (진행자가 시작해 줌) |
| **연구자 화면** | https://projectmuyu.github.io/hci_pilot/search_system.html?view=researcher | 진행자 |

> **가장 중요한 규칙**: 실험은 **한 PC, 한 브라우저(크롬 권장)** 에서 진행합니다.
> 기록은 그 PC의 그 브라우저 안에만 저장됩니다. 다른 브라우저·시크릿 창·다른 PC에서는 기록이 보이지 않습니다.
> 실험이 끝날 때마다 **기록 ZIP을 내려받아 두세요.**

---

## 1. 처음 한 번만 (실험 전 준비)

1. 실험에 쓸 PC에서 크롬으로 **연구자 화면**을 엽니다.
2. "사진을 불러오는 중… n / 200" 화면이 끝날 때까지 기다립니다 (처음 한 번만, 10초~1분).
3. `참여자 기록` 탭 위의 **진행자** 칸에 본인 이름을 적습니다 (예: 의현).
   - 이 이름이 기록과 내보내는 파일에 붙어서, 나중에 세 사람의 결과를 합칠 때 구분됩니다.
   - **첫 참여자 전에** 꼭 넣어 주세요. 넣기 전에 생긴 기록에는 이름이 붙지 않습니다.
4. `사진 풀 관리` 탭에 사진이 200장 들어와 있는지 확인합니다.

## 2. 실험 당일 화면 띄우기

1. **연구자 화면**을 엽니다 (진행자용 창).
2. 오른쪽 위 **`검색 화면 열기 ↗`** 를 눌러 검색 화면을 새 창으로 엽니다 (참여자용 창).
   - 모니터가 두 대면 검색 화면을 참여자 쪽 모니터로 옮기고, 전체 화면(F11)으로 두면 좋습니다.
3. 두 창은 기록을 함께 씁니다. 검색 화면에서 일어난 일이 연구자 화면에 바로 나타납니다.

## 3. 참여자 한 명 진행하기

1. **검색 화면**의 "참여자 시작"에서
   - **진행자**: 자동으로 채워져 있습니다 (비어 있으면 이름 입력)
   - **참여자 ID**: 입력 (예: `P01`) → **시작**
2. 참여자에게 넘깁니다. 참여자는
   - 검색창에 원하는 말을 넣어 검색하고,
   - 마음에 드는 사진의 **하트**를 눌러 담고 (사진을 누르면 크게 볼 수 있음),
   - 위의 **`마음에 든 사진`** 에서 한 장을 골라 **`이 사진으로 결정`** → **`결정`** 을 누릅니다.
3. "선택을 마쳤습니다" 화면이 나오면 참여자가 진행자를 부릅니다.
4. 진행자는 **"연구자에게 알려 주세요."** 를 누릅니다 → 다시 "참여자 시작" 화면이 나옵니다.
5. 기록은 최종 결정 순간 **자동으로 저장**됩니다. 연구자 화면의 `참여자 기록` 탭에서 확인하세요
   (검색어 목록, 담은 사진, 최종 사진, 걸린 시간).

### 참여자 ID
참여자 ID는 **P01~P12를 미리 등록해 진행자별로 나눠 둔 번호**를 그대로 씁니다 (본인에게 배정된 번호만 사용).

### 중간에 멈춰야 할 때
- 연구자 화면 오른쪽 위에 "검색 화면 진행 중 P03 · 담은 사진 n장"이 보입니다.
- **`미완료로 끝내기`** 를 **두 번** 누르면, 그 참여자는 기록에 **미완료**로 남고 검색 화면은 "참여자 시작"으로 돌아갑니다.
- 새로고침을 해도 진행 중이던 상태(검색어, 담은 사진)는 그대로 남아 있으니, 실수로 새로고침해도 괜찮습니다.

### 참여자 ID를 잘못 넣었을 때
연구자 화면 `참여자 기록` 탭에서 해당 기록의 ID 칸을 눌러 바로 고칠 수 있습니다.

## 4. 실험이 끝나면 (매번)

연구자 화면 → `참여자 기록` 탭 → **`기록 + 최종 사진 (ZIP)`** 을 눌러 내려받습니다
(파일 이름 예: `search_participants_의현_2026-10-26.zip`).

ZIP 안에는 이런 것이 들어 있습니다.
- `participants.csv` — 기록 표 (엑셀로 열림)
- `participants.json` — 기록 원본 (나중에 화면에 다시 불러올 때 씀)
- `의현_01_P01/` 같은 참여자별 폴더 — 담은 사진(`liked_…`)과 최종 사진(`FINAL_…`)

기록은 브라우저를 끄거나 PC를 껐다 켜도 남아 있습니다. 하지만 아래 경우에는 **사라지거나 보이지 않으니**, 그날 받은 파일은 공유 드라이브에 올려 두세요.

- 브라우저에서 **인터넷 사용 기록 삭제 → 쿠키 및 사이트 데이터**를 지웠을 때 (지워짐)
- **시크릿 창**에서 진행했을 때 (창을 닫으면 지워짐)
- 크롬 설정의 **"창을 닫을 때 쿠키 및 사이트 데이터 삭제"** 가 켜져 있을 때 (끌 때마다 지워짐)
- 학교·연구실 **공용 PC의 재부팅 복원 프로그램**이 있을 때 (재부팅하면 지워짐) — 실험 PC에 이런 프로그램이 있는지 미리 확인하세요
- 같은 크롬이어도 **다른 프로필**로 열었을 때, 다른 브라우저나 다른 PC일 때 (따로 저장되어 안 보임)

## 5. 결과 합치기 (의현이 모아서)

1. 세 사람이 각자 받은 **기록 ZIP**을 의현에게 보냅니다.
2. 의현이 연구자 화면 → `참여자 기록` 탭 → **`기록 불러오기 (ZIP)`** 에서 받은 ZIP들을 고릅니다 (여러 개를 한 번에 골라도 됨).
   - 세 사람의 기록이 한 화면에 합쳐지고, 다른 사람 기록에는 "불러온 기록" 표시가 붙습니다.
   - 같은 ZIP을 두 번 올려도 기록이 겹치지 않습니다.
   - 진행자가 둘 이상이면 **진행자별로 골라 보기**가 생깁니다.
3. 합친 상태에서 **`기록 + 최종 사진 (ZIP)`** 을 누르면 전체 기록이 한 파일로 나옵니다 (`search_participants_전체_….zip`, 안의 `participants.csv`가 합친 표).
   진행자별로 골라 둔 상태에서 누르면 그 사람 것만 나옵니다.
4. 표에서 참여자는 **`researcher` + `participant_id`** 로 구분합니다. 맨 앞 `no`는 PC마다 1번부터 매겨지므로 사람끼리 겹칩니다.

> 불러온 기록의 사진은 각자 PC에 있는 같은 사진 풀에서 보여 줍니다. 그래서 세 사람이 같은 사진 풀을 써야 사진이 제대로 보입니다.

### 기록 표(`participants.csv`) 열 설명

| 열 | 내용 |
| --- | --- |
| `no` | 그 PC에서의 기록 순번 |
| `researcher` | 진행자 이름 |
| `participant_id` | 참여자 ID |
| `status` | `완료` 또는 `미완료` |
| `started_at`, `finished_at` | 첫 검색(또는 첫 담기) 시각, 결정 시각 |
| `query_count`, `queries` | 검색 횟수, 검색어 목록 (` \| `로 구분) |
| `liked_count` | 마지막에 담겨 있던 사진 수 |
| `liked_with_query` | `사진@검색번호:검색어` — 각 사진을 마지막으로 담은 검색 |
| `unliked_count` | 담았다가 뺀 횟수 |
| `final_query` | 최종 사진을 담은 검색 (`번호:검색어`) |
| `liked_files`, `final_file` | 담은 사진 파일 이름, 최종 사진 파일 이름 |
| `final_in_liked_order` | 최종 사진이 담은 순서로 몇 번째였는지 |

## 6. 사진 태그는 어떻게 달았나

검색 화면은 사진마다 붙은 **태그**로 결과를 고릅니다. 사진 200장에 사진당 평균 16개(11~21개)의 태그를 **13개 분류, 94개 단어** 안에서 달았습니다.

### 태그 다는 규칙
- **꼭 붙인 것**: 분위기 1~2개, 스타일 1~2개, 색 1~3개, 빛·시간대 1개, 생활감 1개(깔끔한·생활감·맥시멀 중 하나)
- **보이면 붙인 것**: 소재·질감, 패턴, 가구, 침대, 조명, 소품·장식, 공간·전망, 반려동물. 작게 보여도 보이면 붙였습니다.
- **방 종류(침실·원룸·작은방·거실)는 붙이지 않았습니다.** 대부분 침대가 있는 혼자 사는 방이라, "침실"이나 "원룸"으로 검색했을 때 결과가 걸러지지 않게 하려는 것입니다.
- **`아늑한`은 확실히 아늑해 보이는 사진에만** 붙였습니다. 너무 흔하면 검색어로 골라내지 못하기 때문입니다.
- 사진에 실제로 보이는 것만, 사람이 검색창에 칠 법한 말로 붙였습니다.

### 검색어는 이렇게 태그와 맞춰집니다
- **영어와 비슷한 말도 찾습니다.** 예: cozy·포근한 → 아늑한, 원목·wood → 우드, 포스터·그림 → 액자, 통창·창가 → 큰창문, 네이비 → 블루, 테라코타 → 오렌지·브라운
- **붙은 말은 떼고 읽습니다.** 베이지톤 → 베이지, 크림색 → 크림(베이지), 호텔처럼 → 호텔, 깔끔하게 → 깔끔한, 소파랑 → 소파
- **방을 가리키는 말은 점수에 넣지 않습니다.** 방, 침실, 원룸, 자취방, 침대, 인테리어, 사진 등
- **평수**: 10평 이하(예: 5평, 6평)는 `좁은`으로 읽습니다.
- **빼고 싶은 것**: "식물 없는", "러그 빼고", "-러그"처럼 쓰면 그 태그가 있는 사진을 뺍니다.
- 태그와 많이 맞는 사진부터 보여 주고, 맞는 사진이 12장보다 적으면 나머지 사진을 섞어 24장까지 채웁니다.

## 7. 사진을 추가하거나 바꾸고 싶을 때

**의현에게 사진 파일을 보내 주세요.** 의현이 중복 확인 → 태그 달기 → 저장소 반영을 합니다.

- 반영되면 각자 PC에서 페이지를 **새로고침**할 때 새 사진이 자동으로 들어옵니다 (이미 받은 사진은 다시 받지 않고, 기록도 그대로 유지).
- 실험 도중 사진이 바뀌면 그 뒤 참여자는 다른 사진 풀로 검색하게 됩니다. **세 사람이 같은 시점에 새로고침**해서 같은 풀을 쓰도록 맞춰 주세요.
- 연구자 화면의 `사진 풀 관리`에서 직접 끌어다 넣은 사진은 **그 PC에만** 들어가고 다른 사람 PC에는 생기지 않습니다. 실험용 사진은 꼭 의현을 통해 추가해 주세요.

## 8. 자주 묻는 것

**Q. 연구자 화면에 기록이 안 보여요.**
검색 화면과 연구자 화면을 **같은 브라우저**에서 열었는지 확인하세요. 크롬과 엣지, 일반 창과 시크릿 창은 서로 기록을 공유하지 않습니다.

**Q. 사진이 안 나오거나 0장이에요.**
인터넷 연결을 확인하고 새로고침하세요. 처음 열 때 사진을 받아야 해서 인터넷이 필요합니다. 그래도 안 되면 연구자 화면 `사진 풀 관리`의 **`기본 풀 다시 맞추기`** 를 누르세요.

**Q. `기본 풀 다시 맞추기`는 언제 누르나요?**
사진 수가 이상하거나 태그가 꼬였을 때만 누릅니다. 저장소의 사진·태그로 다시 맞추며, 직접 고친 태그는 덮어씁니다. 참여자 기록은 지워지지 않습니다.

**Q. 검색 화면에서 연구자 화면으로 가는 버튼이 없어요.**
일부러 없앴습니다 (참여자가 누르지 않도록). 연구자 화면은 따로 열어 둔 창을 쓰세요.

**Q. 파일을 더블클릭해서 열면 사진이 없어요.**
`search_system.html` 파일을 직접 열면 브라우저 보안 때문에 사진을 자동으로 불러오지 못합니다. 위의 **주소로 접속**해서 쓰세요.

**Q. 참여자에게 보이면 안 되는 것이 있나요?**
연구자 화면과 이 문서는 참여자에게 보여 주지 마세요. 참여자는 검색 화면만 봅니다.

### 코드를 고치려면

1. **권한 받기**: 의현에게 GitHub 아이디를 알려 주면 저장소 공동 작업자로 초대합니다 (Settings → Collaborators → Add people). 이메일로 온 초대를 수락하세요.
2. **내려받기**: `git clone https://github.com/projectmuyu/hci_pilot.git`
3. **고친 뒤 확인**: `search_system.html`을 더블클릭하면 사진이 자동으로 들어오지 않습니다. 폴더에서 아래를 실행하고 브라우저로 여세요.
   ```
   python -m http.server
   ```
   → `http://localhost:8000/search_system.html?view=researcher` / `?view=search`
4. **올리기**: `git pull` → `git add` → `git commit` → `git push`
5. **반영**: 1~2분 뒤 GitHub Pages에 반영되고, 각자 새로고침하면 바뀐 버전이 됩니다.

Claude Code를 쓰면 `CLAUDE.md`(구조·저장 방식·주요 함수 정리)를 자동으로 읽어서 이어서 작업하기 쉽습니다.

**주의**
- `main`에 올리면 **바로 모두에게 적용**됩니다. 실험 기간 중에는 고치지 않거나, 세 사람이 시점을 맞추세요.
- 고치기 전에 `git pull`로 최신을 받고, 작업한다고 서로 알리세요 (같은 파일을 동시에 고치면 충돌). 더 안전하게 하려면 브랜치를 만들어 Pull Request로 올리고 의현이 확인 후 합칩니다.
- 아래를 바꾸면 **이미 쌓인 기록이 안 보이거나 기록 불러오기가 안 맞을 수 있습니다**: 저장 이름(`rs_archive`, `rs_pick` 등), 기록 형식(`participants.json` 구조), 사진 id 만드는 방식(`pool_` + 파일 이름).
- 검색 규칙이나 태그를 바꾸면 같은 검색어라도 결과가 달라집니다. 실험 중이면 참여자 간 조건이 달라지니 주의하세요.
- 권한 없이 제안만 하려면 저장소를 Fork해서 고친 뒤 Pull Request를 보내 주세요.
